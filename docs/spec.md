# Tier表メーカー 仕様書

このドキュメントは、本アプリ「Tier表メーカー」がどのような仕組みで動いているかを、Web開発の経験が浅いエンジニアにも分かるようにまとめたものです。

- 本番URL: https://tier-board-app.vercel.app
- リポジトリ: https://github.com/ararin7777-gif/tier-board-app

---

## 1. このアプリは何をするものか

自分専用の「Tier表(ティア表)」を作成・編集・共有できるWebアプリです。

- 何でも自由にランク付け(S/A/B/C/D…のような段に、画像付きのアイテムを並べる)
- 複数のTier表を作って管理できる
- 完成したTier表を「公開リンク」で他人に見せられる(見るだけ/一緒に編集できる、を選べる)
- PCでもスマホでも使える

---

## 2. 技術スタック(何を使って作られているか)

| 分類 | 使用技術 | 役割 |
|---|---|---|
| フレームワーク | [Next.js 16](https://nextjs.org/)(App Router / TypeScript / Turbopack) | 画面の表示とサーバー処理を1つのプロジェクトで行う |
| データベース・認証・画像保存 | [Supabase](https://supabase.com/) | ログイン機能・データ保存(Postgres)・画像ファイル保存(Storage)をまとめて提供するクラウドサービス |
| デザイン | [Tailwind CSS v4](https://tailwindcss.com/) + [shadcn/ui](https://ui.shadcn.com/)([Base UI](https://base-ui.com/)ベース) | 見た目(色・余白・ボタンなどの部品)を作る |
| ドラッグ&ドロップ | [dnd-kit](https://dndkit.com/) | アイテムや段をドラッグして並べ替える機能 |
| ダークモード | [next-themes](https://github.com/pacocoursey/next-themes) | ライト/ダーク切り替え |
| ホスティング | [Vercel](https://vercel.com/) | 完成したアプリをインターネット上に公開する場所 |

### なぜこの組み合わせなのか(初心者向けメモ)

- **Supabase**を使う一番の理由は、「ログイン」「データベース」「画像保存」を別々のサービスで契約・連携する必要がなく、1つの管理画面で完結するからです。個人開発では特に有利です。
- **Next.js**はページの見た目(React)と、裏側の処理(サーバー側のコード)を同じプロジェクト内に書けるフレームワークです。「Server Actions」という仕組みを多用しており、これは画面のボタンから直接サーバー側の関数を呼び出せる機能です(後述)。

## 3. 全体の仕組み(データの流れ)

```
[ブラウザ(あなたの画面)]
        │  クリックやドラッグなどの操作
        ▼
[Next.js が動いている Vercel のサーバー]
        │  Server Actions・proxy.ts 経由でSupabaseへ問い合わせ
        ▼
[Supabase]
   ├─ Auth      … 誰がログインしているかを管理
   ├─ Postgres  … Tier表・段・アイテムのデータを保存
   └─ Storage   … アップロードした画像ファイルを保存
```

ポイントは、**ブラウザが直接データベースを操作するのではなく、必ずSupabase側の「アクセス許可ルール(RLS)」を通る**という点です。これにより「自分のデータしか編集できない」「公開したものだけ他人が見られる」という安全性が保たれています(詳しくは5章)。

---

## 4. データベース設計

3つの表(テーブル)でデータを管理しています。

### `tier_boards`(Tier表本体)

| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid | Tier表のID |
| user_id | uuid | 作成した人(所有者)のID |
| title | text | タイトル |
| is_public | boolean | 公開/非公開 |
| allow_public_edit | boolean | 公開時、他人にも編集を許可するか |
| cover_image_url | text | 一覧に表示するプレビュー画像(未設定なら自動選択) |
| share_slug | text | 共有リンク用のランダムな文字列(例: `xK9pQ2mNwZ`) |
| created_at / updated_at | timestamptz | 作成日時・更新日時 |

### `tiers`(段: S・A・Bなど)

| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid | 段のID |
| board_id | uuid | どのTier表に属するか |
| label | text | 段の名前(最大3文字) |
| color | text | 段の色(16進カラーコード) |
| position | integer | 表示順(小さいほど上位) |

### `items`(アイテム: ランク付けする対象)

| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid | アイテムのID |
| board_id | uuid | どのTier表に属するか |
| tier_id | uuid・NULL可 | どの段に置かれているか(NULLなら「未評価プール」) |
| name | text | アイテム名(空でも可) |
| image_url | text・NULL可 | 画像のURL(Supabase Storage上のファイル) |
| position | integer | 同じ段(またはプール)内での表示順 |

### 関係図

```
tier_boards 1 ── ∞ tiers 1 ── ∞ items
                 (tier_idがNULLのitemsは「未評価プール」扱い)
```

## 5. セキュリティの仕組み(RLS)

Supabaseの**RLS(行レベルセキュリティ)**という機能で、「誰がどのデータを読み書きできるか」をデータベース自身に守らせています。アプリのコード側でチェックが漏れていても、データベースが弾いてくれるという二重の安全策です。

| 操作 | 許可される条件 |
|---|---|
| 読み取り(select) | 本人の所有物、または `is_public = true` のもの |
| 追加・変更・削除(write) | 本人の所有物、または「`is_public = true` かつ `allow_public_edit = true`」でログイン済みの場合 |
| 画像の読み取り | 誰でも可(公開バケット) |
| 画像のアップロード・削除 | 自分のユーザーID配下のパスにのみ可 |

> 補足: Supabaseは新規テーブルへの自動アクセス許可(GRANT)をオフにする設定があり、本アプリではこれをオフにしているため、`schema.sql` 内で明示的にGRANT文を実行しています。RLSは「行単位の絞り込み」、GRANTは「テーブルへのアクセスそのものの許可」という別レイヤーの仕組みです。

## 6. 画面・ルート一覧

| URL | 認証 | 役割 |
|---|---|---|
| `/` | - | `/boards` へリダイレクトするだけ |
| `/login` | 不要 | ログイン画面 |
| `/signup` | 不要 | 新規登録画面(登録後に確認メールが届く) |
| `/auth/callback` | - | メール内の確認リンクから戻ってきた際に、ログイン状態を確定させる裏方のルート(画面はない) |
| `/boards` | 必要 | Tier表一覧(自分の所有物 + 他人の公開Tier表) |
| `/boards/[boardId]` | 必要 | Tier表の編集画面、または閲覧のみの共同編集画面 |
| `/share/[slug]` | 不要 | 公開されたTier表を誰でも見られる閲覧専用ページ |

## 7. 主要機能の仕様

### 7-1. 認証(ログイン)
- メールアドレス+パスワードのみ(ソーシャルログインなし)
- 新規登録時、Supabaseから確認メールが届き、リンクをクリックすると本登録完了
- `proxy.ts`(Next.js 16での名称。旧`middleware.ts`)が全リクエストの手前で「ログインしているか」を確認し、未ログインなら `/login` へ自動的に転送する

### 7-2. Tier表のCRUD
- 新規作成すると、S/A/B/C/Dのプリセット段が自動で用意される
- タイトルはクリックすると直接編集できる(インライン編集)
- 削除には確認ダイアログが必須

### 7-3. 段(Tier)の編集
- 色付きのチップをクリック→編集モード(名前・色を変更)
- 同じチップを**長押し(ドラッグ)**すると、段ごと(中のアイテムも一緒に)並べ替えられる
- 削除は「段の削除」ボタンから、対象を選んで行う(誤操作防止のため、行ごとの常設削除ボタンは廃止した)

### 7-4. アイテムの管理
- 「アイテムを追加」から画像を複数選択し、まとめてアップロード→名前を編集→登録、という流れ
- 対応画像形式: JPEG・PNG・WebP・GIF(iPhoneのHEIC形式は非対応のため選択時に弾かれる)
- アイテムは「未評価プール」と各段の間をドラッグ&ドロップで移動できる
- 削除方法は2通り: ①画像にカーソルを合わせて出る✕ボタン、②ドラッグ中に画面下部へ現れる「ゴミ箱」にドロップ

### 7-5. 公開・共有
- 「公開」に切り替えると共有リンク(`/share/[slug]`)が発行される
- 「他のユーザーも編集可」を追加でONにすると、リンクを知らなくても`/boards`一覧経由でログイン中の他ユーザーが編集画面に入れる(タイトル変更・公開設定・Tier表自体の削除は所有者のみ可能)
- 一覧画面には「自分のTier表」と「他人の公開Tier表」が混在して表示される。公開Tier表を自分が所有していない場合、削除ボタンは表示されない

### 7-6. プレビュー画像(タイトル画面)
- 手動でアップロードした画像があればそれを一覧のプレビューに使用
- 未設定の場合、最も上位の段の一番左のアイテム画像を自動で使用
- どちらもない場合は「プレビューなし」と表示

### 7-7. ダークモード
- OS設定に自動追従、右上のボタンで手動切り替えも可能

### 7-8. 外部サービスからのインポート
- `/boards`の「インポート」から、mintier.jpで作成した既存のTier表のURLを入力すると、タイトル・段構成・色・アイテム画像をまとめて取り込める
- 仕組み: 対象ページのHTML内に埋め込まれた `__NEXT_DATA__` というデータから情報を抜き出し、画像を1枚ずつダウンロードして自分のSupabase Storageへ再アップロードしている

### 7-9. レスポンシブ対応
- スマホ幅(Tailwindの`sm`ブレークポイント未満)では、段のチップやアイテム画像を一回り小さく表示し、限られた画面幅を有効活用している

## 8. ディレクトリ構成(主要ファイル)

```
src/
├─ app/
│  ├─ page.tsx                    … "/" (リダイレクトのみ)
│  ├─ login/page.tsx               … ログイン画面
│  ├─ signup/page.tsx              … 新規登録画面
│  ├─ auth/callback/route.ts       … メール確認リンクの受け口
│  ├─ boards/
│  │  ├─ page.tsx                  … Tier表一覧
│  │  ├─ actions.ts                … 一覧関連のServer Actions(作成・削除・改名)
│  │  ├─ import-actions.ts         … 外部インポート機能のServer Action
│  │  └─ [boardId]/
│  │     ├─ page.tsx               … 編集画面
│  │     └─ actions.ts             … 編集関連のServer Actions(段・アイテム操作)
│  └─ share/[slug]/page.tsx        … 公開閲覧ページ
├─ components/                     … 画面部品(ボタン・ダイアログ・カード等)
├─ lib/supabase/
│  ├─ client.ts                    … ブラウザ用Supabaseクライアント
│  ├─ server.ts                    … サーバー用Supabaseクライアント
│  └─ session.ts                   … ログインセッションの検証・更新ロジック
└─ proxy.ts                        … 全リクエストの手前で走る認証チェック(旧middleware)

supabase/schema.sql                 … DBスキーマ・RLSポリシーの定義(Supabase側に手動で適用)
```

### Server Actionsとは(初心者向け補足)

`"use server"` と書かれたファイル内の関数は、ボタンのクリックなどブラウザ側の操作から**直接呼び出せるサーバー側の処理**です。従来のように「API用のURLを別途作って、fetchで叩く」という手間を省略できる、Next.jsの仕組みです。本アプリのデータ操作(作成・更新・削除)はほぼ全てこの方式で実装されています。

## 9. デプロイ構成

| 項目 | 内容 |
|---|---|
| ホスティング | Vercel(GitHubリポジトリと連携し、`main`ブランチへのpushで自動デプロイ) |
| 環境変数 | `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` / `NEXT_PUBLIC_SITE_URL` |
| Supabase側の設定 | Authentication → URL Configuration の Redirect URLs に本番ドメインを登録 |

開発の流れは、ローカルで実装 → `npm run build` でエラーがないか確認 → Gitにコミット → `git push` → Vercelが自動で本番反映、というサイクルを一貫して繰り返している。
